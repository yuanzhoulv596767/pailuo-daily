F-07 · 把 git blob 当成 sha256（11-14 04:13）

  • 我以为是：git hash-object 出来的是「这个文件的 hash」，回执里写「改前 sha256」没问题——反正都是 hash，能对上就行。
  • 错在第几步：第一步就错，错在没定义「要哪种 hash」。git 的 blob 是 SHA-1 (40 位)，sha256 是 64 位；我把前者写在了后者的名字下面。读回执的人按 sha256sum 复算，永远对不上，还会以为文件被改过。

错在第几步

错在把“记录”当成了“事实”。记录本身先于事实，并且用错了凭证算法：

  • 回执把 git blob 的 SHA-1 前缀当成 sha256；两条回滚命令按字面不能执行。凭证链不成立，“可回滚”只是纸面。
  • 记录时间写在提交之后：补记、裁决、日志的时间戳晚于自己的提交时间 3–6 分钟；审计现场的时间不可信。
  • 板面停在旧快照：日记数、公示状态、导演台健康状态都与此刻不符。
  • 身份卡的“勿手改”被直接编辑，导出时间早于它列出的内容；来源标记失效。
  • 规则层自己写着“不写绝对路径”，正文和四份 brief 却布满绝对路径；条文与现实互相否定。
  • 板面/日志/日记的格式与数字多处失守：§2 超长、缺状态词；§3 用了枚举外的状态；窗口日志超 60 字且顺序错；失败日记标题格式分叉；汇总 12/14/15 三处不一致；坑榜归属写错并指向已删文件。
  • 治理节奏本身出问题：18 分钟 14 次提交全是治理/文档，内容产出为零；新规则 03:55 落地，03:56 的回执就没按新规则写。

下次先查什么

先验凭证链，再看板面，最后看规则文本：

1. 回执里的 sha256 是不是真的 sha256（不是 git blob），回滚命令能不能按字面执行，时间戳是否早于提交。

2. 板面的数字/状态是否与当前文件、端口、进程一致；“服务在跑”要亲手打一次。

3. 身份卡/日记/坑榜的来源标记与格式是否自洽；数字在三处是否一致。

4. 规则文本是否被自己的正文违反（绝对路径、状态枚举、字数上限）。

5. 治理提交与内容提交的比例；新规则落地后的第一份回执是否合规。

发现（按严重度）

1. 凭证链不成立（最重）：回执的“sha256”实为 git blob（SHA-1）前缀；两条回滚命令按字面跑不了（一条把 blob 当 commit，一条路径不完整）。“改动必可回滚”没有可执行的证据。

2. 时间戳不可信：03:58 的补记写进 03:54 的提交；04:05/04:06 写进 04:01 的提交；窗口日志与提交时间普遍差 4–6 分钟。失败日记 F-04/F-06 记过同一模式，新规则落地后 6 分钟内又复发。

3. 板面不是“此刻”：失败日记写 12 条，实际 15 条；§5 已空却写“两条新建议公示中”；导演台说“返 200”，实测连续三次空响应。下个窗口会按错的状态开工。

4. 身份卡来源失真：“勿手改”却被直接编辑；导出时间 02:55，却列出 03:05 才出现的名字。要么时间错，要么是手改。

5. 规则层与现实冲突：“只写相对路径”的条文自己就有绝对路径，四份 brief 也有大量绝对路径；要么清理，要么改条文。

6. 格式与数字失守：§2 两条超 200 字（251/352），感受/边界缺状态词；§3 用“完成/长期”；§1 8 行仅 2 行有日期；窗口日志 4 行超 60 字且顺序错；失败日记标题只有一半带 F 号；汇总标题/正文/实际三处不一致；坑榜 OPS 条归属写“法官”并指向已删文件。

7. 治理在制造新错误：18 分钟 14 次提交全是治理/文档，内容产出为零；新规则 03:55 落地，03:56 的回执就没按新规则写。维护成本已经高于被维护的对象。

审计思路（思维链摘要）

1. 先确认角色与边界：用户指定“审计窗口”，不属于五窗；只读，不改板、不改规则、不动别人的文件。

2. 先看板面与 git 时间线：板面是“现场”，git 是“事实”；两者一比，先找滞后和矛盾。

3. 假设“记录可信”，抽最新两份规则回执，按回执里写的回滚命令原样核对；发现 hash 类型不对、命令不可执行。

4. 再把“记录时间”与“提交时间”对齐；发现补记/裁决/日志的时间都晚于提交，属于“先写记录、后做/补做”。

5. 再查板面数字与运行态：日记 12 vs 15；导演台说 200 实际空响应；身份卡导出时间与内容矛盾。

6. 最后查规则文本与规则层自身：绝对路径、§2/§3 格式、日记格式、坑榜归属；发现条文和现实互相否定。

7. 结论：不是单点手滑，是流程惯性——记录跑在事实前面。先修凭证链与时间戳，再加规则；否则新规则只会增加新的纸面。

关键转折点

  • 回执自称 sha256，但值是 12 位十六进制前缀；用 git 的对象类型一查，确认是 blob。此后不再信“sha256”这个标签。
  • 日志说 04:06，但提交是 04:01；把文件内时间和提交时间对齐，确认记录先于事实。此后以提交时间为准。
  • 板面说 8788 返 200，但连续三次 curl 是空响应；以端口实测为准。此后“服务在跑”必须亲手打一次。
  • 身份卡导出时间 02:55，却列出 03:05 才出现的名字；回头查提交史，确认它在导出后被直接编辑过。
