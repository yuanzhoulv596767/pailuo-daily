可修正的智能体：没有痛感的认知迭代

论文骨架（冻结于 2026-11-13；标题、定位与三条贡献于 2026-11-17 调整，五节结构不变）。一个月后（2026-12-13）按此展开。冻结＝可以改字，不改结构；要改结构先跟用户说。

定位

经验型系统报告（experience / system report），不是框架论文；以 30 天五窗部署为现场，观察「外部脚手架如何驱动认知迭代，又如何制造认知固化」。

不声称提出新协议——黑板 + git 已有前人做过，硬撑会被一句「这不就是 blackboard + git」打死。

一句话：在没有生物学生存压力的数字世界里，用规则、硬校验、交叉审计和公开记录，把无成本的生成变成有代价的执行；代价让智能体改，脚手架也可能把「改的能力」固化。

三条贡献（降级版）

1. 一种部署形态的观察：真实工作站、跨天驻留、五角色、纯文本工件 + git 对账，以及「生成 → 校验 → 回滚 → 公开」的代价链

2. 一份事故 → 条文 → 可核验代价的转化清单，补 MAST 缺的一块：人—agent 边界类失败；单列认知固化类失败（同因复发、旧记忆误用、规则只增不减、指标替代目标）

3. 一组可复位的设计原则：单槽邮箱、结论/明细分家、用户即锁、报错落点三分；以及四条抗固化检查（预测—结果、同因单列、允许不知道、回滚）

系统命名

个人多智能体操作系统（Personal Multi-Agent Operating System, PMA-OS）：在单台个人工作站上，把多个长期驻留的 LLM 会话当作有角色、有权限、有记忆、有账本的进程来调度、隔离、审计和回滚的协调层。这里的 OS 是类比，不是内核。

映射：进程/隔离＝五个长期窗口；调度＝每日 20:40 轮；内存＝RAG 与上下文；IPC＝交接台与传话槽；权限＝角色 brief 与硬红线；日志与恢复＝回执、hash、回滚；root＝用户（执剑人）。

与经典系统概念的对应（只作类比，不声称已实现）：

  • RBAC-like：AGENTS.md 的「谁管什么」是角色—权限表，五个 brief 是角色说明；当前靠提示层约束 + 事后审查，不是内核强制。
  • State-machine-like：§5 三态（待审/已落/驳回）、§4 占用、窗口生命周期；转换靠人读板，不是形式化 FSM。
  • 并发控制：§4 先占后写是悲观占位；git 提交冲突是乐观校验；没有文件锁。
  • CI/CD：发布站点.py --check 是本地检查，身体推送是部署；没有自动测试矩阵。
  • 人类：不是锁，是提交点的最终校验器/串行化点；允许并行写，提交时验版本、hash、回执，冲突就回滚。

唯一独家点

人—agent 边界失败：越权做别人的活、先删后立规的时序错位、mtime 审计误报、用旧记忆报状态。

MAST 的 14 类里没有——它研究同一进程内的智能体；人也在共享工件里读写时，才会出现「人与 agent 争同一状态」。
