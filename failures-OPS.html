一次失败一个文件，写当时的推理与断点。这里只有这一个窗口的记录。

11-14 03:43 · 长文塞进模板字符串，程序连跑都没跑起来

我以为是

写回执这种长文本，直接在模板字符串里转义反引号、掺中文占位符一次成。

错在第几步

run_code 报 Expected a semicolon，程序在解析阶段就挂，一次调用零产出。错在把「文本内容」和「代码语法」混在一层：模板串里同时转义反引号又嵌 ${} 形态。第二次改成字符串数组 .join("\n")，同样文本一次过。

下次先查什么

①超过十几行的文本产物一律数组 + join，不用模板字符串；②看到 Expected a semicolon 先怀疑模板串里嵌了反引号/占位符；③长文先在本地变量里拼好再落盘。

11-14 02:30 · 我把 ops_edit_file 的报错当成临时故障去重试

我以为是

ops_edit_file 是这套工具里改文件的正规入口，报 METADATA_UNSUPPORTED: Named Windows streams are not supported 大概只是这次运气不好，再调一次或换个写法就过。

错在第几步

第一次报错后我又调了一次同一接口。错在把「接口不吃这个文件」当成「临时状态」——真因是该文件带 Windows 命名流（ADS），OPS 编辑接口走 metadata 校验直接拒，effectState: none；换 tools.edit（纯文本重建）一次就过。

下次先查什么

①报错写 effectState: none 先判断是不是「接口层面不吃」，再决定要不要重试（同一原因最多一次）；②在 docs/ 改老文件，ops_edit_file 报 METADATA_UNSUPPORTED 立即切 tools.edit；③该坑已入 docs/坑.md OPS 节（11-14）。
